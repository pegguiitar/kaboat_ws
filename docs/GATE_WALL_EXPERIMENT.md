# Gate 양측 벽 추정 실험 — competition fe75c12 비교

## 판단

아이디어는 가능하다. 같은 방향으로 이어지는 부표를 묶어 양측 경계를 추정하면, 매번 정면의 부표 두 개를 새 게이트로 짝짓는 문제를 줄일 수 있다. 다만 **방향성 거리 하나만으로 두 벽이 보장되지는 않는다.** 좌우 소속 이력, 두 벽의 분리, 유효한 관측 범위와 곡률 제한이 필요하다.

이 결과는 기존 gate 교체 근거가 아니라 별도 실험의 결과다. `src/`의 기존 알고리즘·launch·파라미터는 수정하지 않았다. 실험 코드는 `scripts/experiments/gate_walls/`에만 추가했다. 실행 방법은 [실시간 센서 재생 가이드](GATE_WALL_RVIZ.md)에 정리했다.

각 입력에 동일한 벽 추정기를 적용하고 거리의 기준 방향만 현재 헤딩 / waypoint 방향 / 이전 통로 접선으로 바꿨다. 입력별 최초 쌍은 최신 코드의 쌍 선택 기하와 현재 라이다 확인으로 초기화했다. 이후의 게이트 쌍·참조 부표 위치는 벽 추정에 제공하지 않았다. 따라서 이 실험은 최초 쌍 검증까지 대체한 완전한 새 인식기는 아니다.

## 제안 알고리즘의 구체화

진행 방향 성분을 짧게 계산하는 거리를 사용했다.

```text
방향성 거리 = sqrt((진행 방향 거리 / 3)^2 + 횡방향 거리^2)
```

`3`은 이번 프로토타입의 고정 실험값이며 최적화된 상수가 아니다.

- 기둥 위치는 odom에 기억한다. 배가 조향할 때 과거 부표 좌표와 좌우 정체성이 같이 회전하지 않게 한다.
- 최초 확인된 한 쌍으로 양측 벽의 초기 위치를 정한다.
- 새 부표는 방향성 거리와 기존 벽까지의 잔차로 분류한다. 기존 소속을 바꾸는 데 비용을 둔다.
- 새 점은 기존 같은 쪽 부표와 연결 가능해야 한다. 먼 곳의 외삽 곡선만 보고 새 점을 받아들이지 않는다.
- 각 벽은 최근 주변 이력으로 강건하게 직선 또는 낮은 차수의 곡선으로 맞춘다. 새 관측에 따라 과거의 위치 오차와 통로 굽음을 보정한다.
- 양측 모두 충분한 관측이 있고, 벽 사이 간격과 앞쪽 지지 범위가 유효할 때만 `TRACK`으로 표시한다. 한 쌍만으로 만들어진 평행선은 가설이다.

여기서 `TRACK`은 **벽 형상 추정 조건 충족**이라는 뜻이다. DRI 검사·센서 신선도 검사·모터 주행 허가를 의미하지 않는다.

**해석:** waypoint 기준은 두 입력에서 모두 안정적인 출발점이었다. 검출기 입력에서는 통로 접선 기준도 비슷하게 작동했다. 반면 지도 입력의 접선 방식은 일부 구간에서 자기 추정이 과하게 휘어, 벽 교차 또는 간격 위반으로 보류됐다. 유효한 구간에서 중앙선 오차가 작아도, 보류가 많으면 더 좋은 알고리즘이라고 할 수 없다.

이 수치는 주행 성공률이 아니다. 벽 형상 유효 장면은 양측 관측 수·길이·예측 간격 등 프로토타입 조건을 만족한 비율이다. 좌우 분류는 참조 부표 0.8m 안의 분류된 기억 점 관측들에 대해 계산했다. 같은 부표가 여러 프레임에서 반복 계산된다.

중앙선 오차는 두 벽이 지지하는 앞쪽 구간과 참조 중점들을 잇는 선 사이 횡방향 차이다. 참조 부표는 저장소의 `scripts/gate_sim/gates_20261112.json`에 있는 **같은 bag에서 정리한 대략적 좌표**다. 측량 정답이나 독립 검증 데이터가 아니며, 지도 계열에 유리한 편향도 가능하다. 이 데이터에서 조정하고 확인한 결과이므로 다른 주행으로 재검증해야 한다.

## 최신 gate와의 장단점

| 관점 | 최신 competition gate | 양측 벽 방식 |
|---|---|---|
| 핵심 표현 | 통과할 부표 쌍과 중점의 사슬 | 좌우 경계와 그 사이 통로 |
| 연속성 | PostMemory와 최대 3개 게이트 사슬로 이미 이력을 사용 | 더 긴 동일 측면의 관측을 함께 묶기 쉬움 |
| 기대 장점 | 각 게이트 통과를 직접 검증하기 쉬움 | 대각선 오쌍을 줄이는 통로 방향·폭의 사전정보 제공 |
| 주요 위험 | 부분 검출에서 오쌍, 경로 검사 중 정지·재선택 | 양쪽 군집 합침, 초기 오분류 고착, 한쪽 누락, 곡선 외삽·교차 |
| 완료 판정 | 7쌍 실제 횡단 및 gate_end 접근 | 벽만으로는 7쌍 통과를 증명하지 못함 |
| 안전 검사 | DRI·실제 점유 셀 여유·lookahead 검사 | 별도로 유지해야 함 |

기존 gate도 이미 과거 정보를 사용한다. 새 방식의 추가 가치는 기억 자체보다 **같은 쪽의 경계를 하나의 통로로 추정해 쌍 선택과 경로의 일관성을 보강하는 것**에 있다.

최신 gate를 같은 기록 입력에 재생했을 때 네 번째 시작 구간에서는 7개 게이트가 참조 순서대로 계산됐다. 이것 역시 기록된 배 궤적 위에서의 판단 재생이며, 새 명령에 따라 배가 달라진 폐루프 결과는 아니다. 이 실험의 벽 유효 비율과 기존 gate의 주행·완료 비율은 서로 다른 지표라 우열 수치로 직접 비교하지 않았다.

## 예상 문제와 필요한 조건

1. **방향성 보상만으로는 대각선이 더 가까울 수 있다.** 폭 2.4m, 다음 게이트까지 3.5m, 좌우 어긋남 1.3m라면 같은 벽 다음 부표의 거리는 약 1.75지만 반대쪽 대각선 부표는 약 1.60이다. 두 벽 분리와 이력 제약이 필수다.
2. **현재 헤딩은 조향 중 흔들린다.** waypoint를 약한 장기 기준으로 두고, 양측 벽이 충분히 관측될 때만 통로 접선으로 제한적으로 보정하는 쪽이 적절하다. 한쪽 벽만으로 추정 방향을 크게 바꾸면 자기 오류가 증폭된다.
3. **첫 쌍이나 초기 기울기를 잘못 잡으면 이력이 오류를 고착시킬 수 있다.** 작은 초기 위치 오차가 보정되는 것은 단위 테스트했지만, 잘못된 게이트를 처음 선택한 경우까지 복구됐다고 검증한 것은 아니다. 신뢰도 하락 시 재초기화 또는 복수 가설이 필요하다.
4. **관측 범위 밖 외삽은 위험하다.** 마지막 관측 뒤까지 두 곡선을 무제한 늘리지 말고, 공통으로 관측된 구간까지만 주행 경계로 사용해야 한다. 특히 전역 다항식 대신 국소 polyline/spline과 곡률 제한을 검토할 필요가 있다.
5. **가상의 벽을 실제 점유 장애물로 합치지 않는 것이 좋다.** 불확실한 경계는 쌍 선택과 경로 비용의 제약으로 사용하고, 충돌 판정은 실제 지도와 스캔으로 계속 확인해야 한다.
6. **벽 추정과 게이트 통과 수는 별개다.** 중앙선을 잘 따라가도 게이트 하나를 건너뛸 수 있다. 기존 gate crossing 판정을 유지해야 한다.

## 권장 구조

```text
부표 후보(검출기 또는 지도)
  → odom의 좌우 이력
  → waypoint 방향을 기준으로 방향성 군집화
  → 신뢰도 있을 때만 통로 접선으로 보정
  → 좌우 벽·중앙선·폭 추정
  → 기존 게이트 쌍 선택/중점 경로에 제약 제공
  → 기존 DRI·점유지도·스캔 안전 검사
  → 기존 LOS 및 통과 횟수 판정
```

장기적으로는 검출기의 개별 랜드마크를 경계 추정에 쓰고 점유지도를 안전 검사에 유지하는 조합이 유망하다. 다만 이번 데이터에서 전체 교체가 우월하다고 검증한 것은 아니다. **현재 gate를 유지하면서 벽을 보조 정보로 사용하는 실험부터** 이어가는 것을 권한다.

## RViz 검증과 결과물

RViz 검증은 두 단계로 수행했다.

1. **저장된 벽 추정 결과 재생:** 별도 컨테이너의 가상 화면에서 마커와 정적 TF를 표시했다. 아래 GIF·정지 화면은 이 단계의 결과다. 기존 gate의 주행 명령 발행은 분석 중 모두 가로챘다.
2. **실제 센서 재생과 실시간 계산:** 사용자 화면에 RViz를 띄우고, 원본 bag의 센서 구간을 반복 발행했다. 최신 부표 검출기·점유지도·기존 gate·실험 벽 추정기를 실제로 실행했다. 이 단계는 저장된 벽 마커만 재생하는 방식이 아니다.

두 번째 단계의 구성과 확인 내용:

- 원본 센서 구간: **2026-11-12 15:31:05~15:33:10 KST**, 125초, 25,025개 센서·TF 메시지.
- `/scan`·`/scan/level`·`/odom`·`/imu/data`·카메라 RGB·camera_info·TF를 재생했다. 기록된 점유지도나 경로는 재생하지 않고 새로 계산했다.
- `/scan/flat`은 실제 스캔을 odom 평면에 표시하기 위한 보조 표현이다. 원본 스캔도 별도로 유지한다.
- **흰색** `/gate/path`: 최신 competition gate의 경로.
- **주황색** `/wall_corridor/detector/path`: 부표 검출기 입력을 사용한 벽 기반 중앙 경로.
- **하늘색** `/wall_corridor/grid/path`: 점유지도 입력을 사용한 벽 기반 중앙 경로.
- 실시간 벽 추정은 거리 기준을 `waypoint`로 사용했다. 위 세 방향 비교와 기존 저장 결과 그림의 `adaptive` 조건과 구분한다.
- 순간 확인값: LiDAR 점 362개, 점유 셀 116개, 부표 마커 배열 항목 35개. 세 경로 좌표 수는 각각 81·48·49개였다. 시점에 따라 달라지는 연결 확인값이며 정확도 지표가 아니다.
- 표시에 초기 가설 경로도 포함한다. 화면 상태가 `TRACK`이 아니면 형상 추정이 보류된 가설이며, 주행 가능한 경로로 검증된 것이 아니다.
- 도메인 97, 로컬 통신에서 미리보기로 실행했다. `cmd_mux`와 모터 드라이버는 실행하지 않았다.

사용자 화면의 최종 RViz 캡처는 시스템 캡처 제한으로 저장하지 못했다. 아래 이미지를 두 번째 단계의 직접 캡처로 해석하면 안 된다.

저장된 결과만 확인하는 일반 ROS 재생 (실시간 센서 실행은 [별도 가이드](GATE_WALL_RVIZ.md) 참조):

```bash
source /opt/ros/humble/setup.bash

```

원본 bag으로 재분석하려면 ROS 환경과 kaboat_msgs가 준비된 상태에서 `analyze_bag.py <bag 절대경로> <결과폴더>`를 실행하고 `score.py <결과폴더/replay.json.gz> <결과폴더>`로 집계한다. 이번 분석은 별도의 임시 ROS 환경에서 수행했다.
